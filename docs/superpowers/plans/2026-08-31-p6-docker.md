> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 把 push2xteink 打包成单容器：`Dockerfile` + `docker-compose.yml` + `.dockerignore` + `README.md`，容器时区可配，健康检查，`./data` 卷持久化 `config.yaml` / `state.db`；并补上 `seen_items` 定期清理（spec §13/§14 唯一遗留项）。

**Architecture:** `python:3.12-slim` 基础镜像，`pip install .`（hatchling 已把 `web/templates`、`web/static` 打进 wheel），非 root 用户，`CMD ["python","-m","push2xteink"]`（exec form，PID 1 收 SIGTERM）。compose 挂 `./data:/data`、注入 `CONFIG_PATH`/`DB_PATH`/`PORT`/`WEB_PASSWORD`/`TZ`、`stop_grace_period: 150s`（P4 `drain_timeout` 120s + 余量）。`seen_items` 清理：`State.prune_seen_items` + `Scheduler` 内部一个每日 job。

**Tech Stack:** Docker / docker-compose、`python:3.12-slim`。代码改动仅 `state.py`（一个方法）+ `scheduler.py`（一个内部 job）。

**Spec:** `docs/superpowers/specs/2026-08-31-push2xteink-design.md` 第 10 节（部署）、第 13/14 节（`seen_items` prune、容器 TZ / tzdata、`PYTHONUNBUFFERED`、`stop_grace_period`、单 worker、明文密钥）。

## Global Constraints

- Python `>=3.12`；`X | None` / `list[...]`。
- Docker 在本开发环境**不可用**——Task「构建与冒烟」是给用户执行的手动步骤，计划给出确切命令 + 预期输出；实现者只做能自动化的部分（prune 代码 + 测试、wheel 内容检查、Dockerfile/compose 静态正确性自检）。
- 镜像里**不装 dev 依赖**（`pip install .` 不带 `[dev]`）。
- 容器以**非 root** 运行；`/data`（bind mount 目录）必须对该 uid 可写——`config.yaml` / `state.db` / `config.yaml.tmp` / `state.db-wal` 都写在那。
- `CMD` 用 exec form `["python","-m","push2xteink"]`，让 python 是 PID 1、直接收 `docker stop` 的 SIGTERM → uvicorn → lifespan 关停（watcher → `scheduler.shutdown()` drain → `state.close()`）。
- **单 worker**：`serve` 传的是 app 对象不是 import string，`uvicorn --workers` 走不到——但 README 要写明「此进程必须单 worker，调度器在进程内」。
- 明文密钥事实必须在 README 写明：`config.yaml` 存 xteink 密码 + AI key 明文；建议 `chmod 600`，不加 `WEB_PASSWORD` 不要把端口暴露到公网。
- cron 表达式按**容器时区**解释（`TZ` 环境变量，默认 `UTC`）；APScheduler 星期 `0`=周一。

## Task 1: `State.prune_seen_items` + `Scheduler` 每日清理 job

**Files:** Modify `src/push2xteink/state.py`, `src/push2xteink/scheduler.py`; Modify `tests/test_state.py`, `tests/test_scheduler.py`

**Interfaces:**
- Produces: `State.prune_seen_items(before_iso) -> int`；`Scheduler` 启动后有一个 `__prune__` 每日 job。

**行为：**
- `prune_seen_items`：`with self._lock:` `DELETE FROM seen_items WHERE pushed_at IS NOT NULL AND first_seen_at < ?`，参数 `before_iso`；返回 `cur.rowcount`；commit。**绝不删 `pushed_at IS NULL` 的行**（那些在重试窗口内）。
- `Scheduler`：加常量 `_SEEN_RETENTION_DAYS = 90`、`_PRUNE_JOB_ID = "__prune__"`。加私有 `_prune(self)`：`cutoff = (_utcnow() - timedelta(days=_SEEN_RETENTION_DAYS)).isoformat()`；`n = self._state.prune_seen_items(cutoff)`；`logger.info("pruned %d old seen_items rows", n)`。
- `start()`：`_register_jobs()` 之后 `self._aps.add_job(self._prune, CronTrigger(hour=3, minute=17), id=_PRUNE_JOB_ID, replace_existing=True)`。
- `_register_jobs()` 用 `remove_all_jobs()`——所以 reload 会把 `__prune__` 也删掉。**修正**：`_register_jobs()` 改成只 remove 非 `__prune__` 的 job（遍历 `get_jobs()` 按 id 删），或在 `_register_jobs()` 末尾无条件重加 `__prune__`。选后者（简单）：把加 `__prune__` 的逻辑提取成 `_ensure_prune_job()`，`start()` 和 `_register_jobs()`（在 `remove_all_jobs` 之后）都调它。
- `_prune` 的异常隔离：包 try/except（`prune_seen_items` 里 sqlite 出错不该让调度线程崩）——`logger.exception` 即可。

# tests/test_state.py
from datetime import datetime, timedelta, timezone

def test_prune_seen_items_only_removes_pushed_and_old(tmp_path):
    s = State(tmp_path / "s.db")
    now = datetime(2026, 8, 31, tzinfo=timezone.utc)
    old = (now - timedelta(days=120)).isoformat()
    recent = (now - timedelta(days=10)).isoformat()
    cutoff = (now - timedelta(days=90)).isoformat()
    s._conn.executemany(
        "INSERT INTO seen_items(feed_id,item_guid,first_seen_at,pushed_at) VALUES(?,?,?,?)",
        [
            ("f", "old_pushed", old, old),        # delete
            ("f", "old_unpushed", old, None),     # keep (retry window semantics)
            ("f", "recent_pushed", recent, recent),  # keep (not old)
        ],
    )
    s._conn.commit()
    n = s.prune_seen_items(cutoff)
    assert n == 1
    rows = {r["item_guid"] for r in s._conn.execute("SELECT item_guid FROM seen_items")}
    assert rows == {"old_unpushed", "recent_pushed"}
    s.close()

```dockerfile
FROM python:3.12-slim

ENV PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1 \
    CONFIG_PATH=/data/config.yaml \
    DB_PATH=/data/state.db \
    PORT=8080

# tzdata so a non-UTC TZ env resolves (APScheduler needs it)
RUN apt-get update && apt-get install -y --no-install-recommends tzdata \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# deps first for layer caching
COPY pyproject.toml README.md ./
COPY src ./src
RUN pip install --no-cache-dir .

# non-root; /data is a bind mount, must be writable by this uid
RUN useradd --system --uid 10001 --home /home/app --create-home app \
    && mkdir -p /data && chown app:app /data
USER app

EXPOSE 8080

HEALTHCHECK --interval=30s --timeout=5s --start-period=15s --retries=3 \
    CMD python -c "import urllib.request,os,sys; sys.exit(0 if urllib.request.urlopen(f'http://127.0.0.1:{os.environ.get(\"PORT\",\"8080\")}/healthz', timeout=4).status==200 else 1)"

CMD ["python", "-m", "push2xteink"]
```

要点：
- `COPY pyproject.toml README.md ./` 在前——`pip install .` 需要 `README.md`（`[project]` 可能 readme 引用它；若 pyproject 没引用可省，但留着无害）。若构建报缺 README，Task 4 会创建它，调整 COPY 顺序即可。
- `HEALTHCHECK` 用 `python urllib`（slim 镜像没有 `curl`）；`/healthz` 已被 auth 中间件豁免（P5），无需 `WEB_PASSWORD`。
- 不 `COPY` `data/`（`.dockerignore` 已排除）；`/data` 靠 compose 挂载。
- `chown app:app /data`：镜像内建的 `/data` 归 app；bind mount 时宿主目录权限接管——README 要提示宿主 `chown 10001` 或用 `user:` 覆盖。

- [ ] **Step 2: `docker-compose.yml`**

```yaml
services:
  push2xteink:
    build: .
    image: push2xteink:local
    restart: unless-stopped
    stop_grace_period: 150s          # P4 drain_timeout(120s) + 余量
    ports:
      - "${PORT:-8080}:8080"
    environment:
      PORT: "8080"
      TZ: "${TZ:-UTC}"
      WEB_PASSWORD: "${WEB_PASSWORD:-}"
      CONFIG_PATH: /data/config.yaml
      DB_PATH: /data/state.db
    volumes:
      - ./data:/data
```

要点：
- `stop_grace_period: 150s`——否则 `docker stop` 10s 后 SIGKILL 会打断正在跑的 `push_file`（安全但吵，spec §14）。
- 容器内始终监听 8080；对外端口用 `${PORT}` 映射。
- `./data` 首次为空——`serve` 会写样例 `config.yaml` 并退出 2，`restart: unless-stopped` 会不停重启直到用户填好配置（可接受，日志里有清晰提示）。README 说明。
- 不设 `user:`——README 给「宿主 `sudo chown -R 10001:10001 ./data`」或「compose 加 `user: "${UID}:${GID}"`」两种方案。

- [ ] **Step 3: 自检**：`docker compose config` 不可用（无 docker）——改用 `python -c "import yaml; yaml.safe_load(open('docker-compose.yml')); yaml.safe_load(open('.env.example').read().replace('=', ': ',1)) if False else None; print('compose yaml ok')"`（只验 YAML 合法）。**Commit** `build: docker-compose.yml + .env.example`

   - 所有 cron 表达式按容器 `TZ` 解释（默认 UTC）。改 `TZ` 后 `docker compose up -d` 重建。

   - 单进程单 worker（调度器在进程内，多 worker 会重复推送）。
   - `docker compose logs -f` 看调度和执行日志。
   - `state.db` 存执行历史和去重记录，会随 `data/` 卷持久化；`seen_items` 里已推送的旧记录 90 天后自动清理。
   - 优雅停止：`docker compose stop`（最多等 150s 让正在跑的任务收尾）。
8. **本地开发**（非 Docker）：`pip install -e ".[dev]"`；`python -m pytest`；`python -m push2xteink --config data/config.yaml --db data/state.db serve` / `list` / `run <task_id>`。
